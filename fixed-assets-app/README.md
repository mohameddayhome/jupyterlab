# الإدارة المالية — الأصول الثابتة والمحاسبة (الإصدار 14)

تطبيق ويب مبني على **Google Sheets + Google Apps Script + HTML**، بواجهة تشبه Microsoft Dynamics 365 Finance & Operations، ومتوافق معه في أسماء الحقول لتسهيل نقل البيانات.

## محتويات المجلد

| الملف | الوظيفة |
|---|---|
| `Code.gs` | الخادم: قاعدة البيانات، الصلاحيات، الجلسات، الحفظ والاستيراد والترحيل |
| `Index.html` | هيكل الصفحة |
| `Styles.html` | التنسيقات (ألوان وشكل D365) |
| `App.html` | منطق الواجهة (كل الصفحات) |
| `appsscript.json` | إعدادات المشروع |

## خطوات التشغيل (10 دقائق)

1. أنشئ **Google Sheet** جديداً وسمّه مثلاً `Fixed Assets DB`.
2. من القائمة: **Extensions ← Apps Script**.
3. أنشئ الملفات بنفس الأسماء وانسخ محتواها:
   - `Code.gs` (ملف Script)
   - `Index` و `Styles` و `App` (ملفات HTML — اكتب الاسم بدون `.html`)
   - لإظهار `appsscript.json`: **Project Settings ← Show "appsscript.json"** ثم الصق المحتوى.
4. من المحرر اختر الدالة `setup` واضغط **Run** ووافق على الصلاحيات.
   ستُنشأ الشيتات تلقائياً + المستخدم الافتراضي.
5. (اختياري) شغّل `seedDemoData` لإضافة الأصل التجريبي `BLD_00001` الموجود في الصور.
6. **Deploy ← New deployment ← Web app**:
   - Execute as: **Me**
   - Who has access: **Anyone** (الدخول محمي بشاشة الدخول الخاصة بالتطبيق)
7. افتح الرابط وسجّل الدخول:
   - المستخدم: `admin`
   - كلمة المرور: `Admin@123` ← سيُطلب منك تغييرها فوراً.

> عند تعديل الكود لاحقاً: **Deploy ← Manage deployments ← Edit ← New version**.

## الصفحات

1. **الأصول الثابتة**: رقم الأصل، المجموعة، الاسم، الموديل، تاريخ الضمان، النوع، الكمية، الموقع، الإدارة، رقم الغرفة، الموظف المسؤول. مع لوحة "معلومات ذات صلة" تعرض دفاتر الأصل.
2. **دفاتر الأصول (Books)**: قائمة جانبية + تفاصيل الدفتر مثل D365. العمر بالسنوات يحسب الفترات بالشهور تلقائياً، والأبعاد المالية الثلاثة متسلسلة (الفرعية تتصفّى حسب الأب).
3. **يومية الأصول الثابتة**: دفعات يومية بأرقام تلقائية `FAJ-000001`، أسطر (تاريخ، اسم اليومية، نوع المعاملة، الأصل، الوصف، مدين، دائن، الحساب المقابل + الأبعاد).
   - دورة العمل: **مسودة ← اعتماد ← ترحيل**.
   - الترحيل يحدّث الدفتر: الاقتناء يضيف للسعر ويفتح الدفتر، الإهلاك يحدّث تاريخ آخر إهلاك وينقص الفترات المتبقية، البيع/التخريد يغيّر الحالة.
4. **الموردون**: رقم المورد، الاسم، العنوان، البريد.
5. **المستخدمون والصلاحيات**: شكل الجدول كما في الصورة. لكل مستخدم صلاحيات لكل صفحة: دخول، إضافة، تعديل، حذف، اعتماد، ترحيل.
6. **الإعدادات**: الشعار، اسم المؤسسة، البريد، العملة، صيغة التاريخ للاستيراد، بادئة رقم اليومية، مدة الجلسة، أقصى عدد جلسات، عرض الجلسات النشطة وإنهاؤها، والقوائم المرجعية (المجموعات، المواقع، الإدارات، الوحدات التشغيلية، أسماء اليوميات، الحسابات).

## النقل من Dynamics 365

**الطريقة:** من D365 صدّر البيانات إلى Excel (من زر **Open in Excel** أو من **Data management ← Export**)، ثم في التطبيق اضغط **استيراد من Excel**.

- يقبل `.xlsx` و `.csv`.
- يتعرّف تلقائياً على أسماء الأعمدة سواء كانت أسماء الكيان (`FIXEDASSETNUMBER`) أو العناوين الإنجليزية (`Fixed asset number`) أو العربية.
- السجل الموجود يُحدَّث، والجديد يُضاف، والأخطاء تظهر برقم السطر.
- **الترتيب المقترح:** القوائم المرجعية ← الأصول ← الدفاتر ← الموردون ← اليوميات.

| صفحة التطبيق | كيان D365 المقابل | أهم الأعمدة |
|---|---|---|
| الأصول | Fixed assets V2 | `FIXEDASSETNUMBER`, `FIXEDASSETGROUPID`, `NAME`, `ASSETTYPE`, `MODEL`, `GUARANTEEDATE`, `LOCATION` |
| الدفاتر | Fixed asset books V2 | `FIXEDASSETNUMBER`, `BOOKID`, `ACQUISITIONDATE`, `STATUS`, `SERVICELIFE`, `DEPRECIATIONPERIODS` (`LIFETIME`), `DEPRECIATIONPERIODSREMAINING` (`LIFETIMEREST`), `SCRAPVALUE`, `DEFAULTDIMENSIONDISPLAYVALUE` |
| اليومية | Fixed asset journal line | `JOURNALBATCHNUMBER`, `TRANSDATE`, `JOURNALNAME`, `TRANSACTIONTYPE`, `FIXEDASSETNUMBER`, `TEXT`, `DEBITAMOUNT`, `CREDITAMOUNT`, `OFFSETACCOUNTDISPLAYVALUE` |
| الموردون | Vendors V2 | `VENDORACCOUNTNUMBER`, `VENDORORGANIZATIONNAME`, `ADDRESS`, `PRIMARYEMAILADDRESS` |

- الأبعاد المالية تُكتب بصيغة D365: `HE01-DJI_HE0101-DJI_HE010001`. إذا استوردت عمود `DEFAULTDIMENSIONDISPLAYVALUE` فقط، يقسّمه التطبيق تلقائياً على الحقول الثلاثة.
- **التصدير** يستخدم نفس أسماء أعمدة D365، فيمكن رفع الملف إلى D365 عبر Data management.
- زر **قالب الاستيراد** ينزّل ملفاً فارغاً بالأعمدة الصحيحة.

## الأمان

- كلمات المرور مشفّرة (SHA-256 مع Salt و 300 تكرار) ولا تُخزَّن كنص.
- رمز الجلسة لا يُحفظ في الشيت، فقط بصمته (Hash).
- قفل الدخول 15 دقيقة بعد 5 محاولات فاشلة.
- انتهاء الجلسة تلقائياً بعد مدة عدم النشاط المحددة، وحد أقصى للجلسات لكل مستخدم.
- كل عملية يتم التحقق من صلاحيتها في الخادم وليس الواجهة فقط.
- لا يمكن حذف/إيقاف آخر مدير عام، ولا يستطيع المستخدم منح صلاحية لا يملكها.

> **مهم:** شيت قاعدة البيانات نفسه يجب ألا يُشارك إلا مع المسؤول، لأن من يفتح الشيت يرى كل البيانات.

## المرحلة الثانية (الإصدار 2)

> **للترقية من الإصدار 1:** انسخ الملفات الأربعة الجديدة فوق القديمة، ثم شغّل `setup` مرة واحدة (تُضاف الأعمدة والشيتات الجديدة بدون حذف أي بيانات)، ثم **Deploy ← Manage deployments ← Edit ← New version**.

| الصفحة | المحتوى |
|---|---|
| **لوحة المعلومات** | بطاقات: عدد الأصول، قيمة الأصول، مجمع الإهلاك، صافي القيمة + مخطط أعمدة لقيمة الأصول حسب الوحدة التشغيلية الرئيسية |
| **الوحدات التشغيلية** | الوحدة الرئيسية ← الفرعية 1 ← الفرعية 2 (كود + اسم + الأب) مع عرض شجري |
| **المواقع والمسؤولون** | المواقع، المباني، الغرف (تتبع المبنى)، الإدارات، الموظفون المسؤولون |
| **دليل الحسابات** | رقم الحساب، اسم الحساب، مجموعة الحساب الرئيسي، نوع الحساب — يستورد من D365 (Main accounts) |
| **الإهلاك التلقائي** | اختر السنة والربع ← حساب المقترح ← إنشاء يومية إهلاك ← اعتماد ← ترحيل |
| **التقارير** | سجل الأصول، ملخص حسب الوحدة التشغيلية، ملخص حسب الموقع/الإدارة/المبنى/المجموعة/الموظف، حركات الإهلاك — مع تصدير Excel وطباعة |

### معادلة الإهلاك

```
الإهلاك = سعر الاقتناء ÷ العمر الافتراضي (سنوات) ÷ 12 × عدد الشهور   (يُسجَّل بالسالب = دائن)
مثال: 730,000 ÷ 50 ÷ 12 × 3 = 3,650 لكل ربع سنة
```

- يبدأ الحساب من الشهر التالي لـ "تاريخ آخر إهلاك" حتى نهاية الربع. لو كان الأصل متأخراً عدة أرباع، يُحسب الفرق كاملاً ويظهر بعلامة **استدراك**.
- لا يتجاوز الفترات المتبقية، ولا ينزل بصافي القيمة تحت قيمة الخردة.
- الأصل الذي له يومية إهلاك غير مُرحّلة يُستبعد حتى لا يتكرر الإهلاك.
- الترحيل يحدّث في الدفتر: مجمع الإهلاك، صافي القيمة، تاريخ آخر إهلاك، الفترات المتبقية.

### عند نقل الأصول من D365
استورد في الدفاتر عمود **مجمع الإهلاك** (`ACCUMULATEDDEPRECIATION`) و**تاريخ آخر إهلاك** (`LASTDEPRECIATIONDATE`) حتى يبدأ الإهلاك من المكان الصحيح ولا يُحسب مرة ثانية.

### الصلاحيات الجديدة
أُضيفت صفحات صلاحيات: **الإهلاك التلقائي**، **التقارير**، **البيانات الأساسية والحسابات**. المستخدمون الحاليون يأخذونها تلقائياً حسب دورهم، ويمكن تعديلها من صفحة المستخدمين.

## الإصدار 3: الربط المحاسبي والشجرة

> **للترقية:** انسخ الملفات الأربعة، شغّل `setup` مرة واحدة، ثم انشر نسخة جديدة. البيانات القديمة في شيت `Lookups` تُنقل تلقائياً للشيتات الجديدة، ويُعاد تسمية القديم إلى `Lookups_archive` (لا يُحذف).

### أين تُحفظ البيانات (كل نوع في شيت مستقل)

| الشيت | المحتوى | الأعمدة |
|---|---|---|
| `OperatingUnits` | الوحدات الرئيسية | CODE, NAME |
| `Sub1OperatingUnits` | الوحدات الفرعية 1 | CODE, NAME, PARENT (الرئيسية) |
| `Sub2OperatingUnits` | الوحدات الفرعية 2 | CODE, NAME, PARENT (الفرعية 1) |
| `Locations` / `Buildings` / `Rooms` | الموقع ← المبنى ← الغرفة | CODE, NAME, PARENT |
| `Departments` / `Employees` | الإدارات والموظفون | CODE, NAME |
| `JournalNames` | أسماء اليوميات | CODE, NAME |
| `AssetGroups` | مجموعات الأصول وحساباتها | FIXEDASSETGROUPID, NAME, ASSETACCOUNT, ACCUMDEPACCOUNT, DEPEXPENSEACCOUNT, DISPOSALACCOUNT |
| `MainAccounts` | دليل الحسابات | MAINACCOUNTID, NAME, ACCOUNTLEVEL (Header/Posting), PARENTACCOUNT, MAINACCOUNTCATEGORY, MAINACCOUNTTYPE |

### الربط المحاسبي

```
الأصل ← مجموعة الأصل ← حسابات الدليل
            ├─ حساب الأصل (اقتناء / بيع / تخريد)
            ├─ حساب مجمع الإهلاك (الطرف الدائن في الإهلاك)
            ├─ حساب مصروف الإهلاك (الحساب المقابل للإهلاك)
            └─ حساب أرباح/خسائر الاستبعاد (المقابل للبيع والتخريد)
المورد ← حساب في الدليل (المقابل لاقتناء الأصل من المورد)
```

- **دليل الحسابات شجري:** حساب رئيسي (Header) يجمع حسابات فرعية (Posting). الترحيل والربط يتم على **الحسابات الفرعية فقط**.
- **سطر اليومية:** "حساب الأصل في القيد" يُملأ من المجموعة حسب نوع المعاملة، و"الحساب المقابل" يُملأ تلقائياً:
  - إهلاك ← حساب مصروف الإهلاك للمجموعة.
  - بيع/تخريد ← حساب الاستبعاد للمجموعة.
  - اقتناء من مورد ← حساب المورد في الدليل.

### الوحدات والمواقع (شجرة)
- في الأصل تسجّل **الوحدة الفرعية 2** فقط، ويكتب النظام الفرعية 1 والرئيسية من الشجرة.
- تختار **الغرفة** فيُكتب المبنى والموقع.
- الدفتر يأخذ وحداته من الأصل تلقائياً، وسطر اليومية يأخذها من الأصل افتراضياً.
- لا يمكن حذف وحدة/موقع له عناصر تابعة، ولا حساب رئيسي له حسابات فرعية أو حساب مستخدم.

### معادلة الإهلاك (القسط الثابت على العمر المتبقي — مثل D365)

```
الإهلاك الشهري = (صافي القيمة الدفترية − قيمة الخردة) ÷ فترات الإهلاك المتبقية
إهلاك الربع   = الإهلاك الشهري × 3   (يُسجَّل بالسالب = دائن)

مثال BLD_00001: (565,750 − 1) ÷ 465 = 1,216.665 شهرياً ← 3,649.99 للربع
```

### ترتيب الاستيراد من D365
دليل الحسابات ← الوحدات (الرئيسية ثم الفرعية 1 ثم 2) ← المواقع/المباني/الغرف ← مجموعات الأصول ← الموردون ← الأصول ← الدفاتر ← اليوميات.

## الإصدار 4: الباركود ونقل الأصول

> **للترقية:** انسخ الملفات الأربعة (`Code.gs` و`App` و`Styles` و`Index`)، شغّل `setup` مرة واحدة (يُنشئ شيت `AssetTransfers`)، ثم انشر نسخة جديدة.

### تسجيل الدخول
- الجلسة تُحفظ **للتبويب الحالي فقط**: إغلاق التبويب أو المتصفح يتطلب تسجيل الدخول مجدداً، وتحديث الصفحة لا يُخرجك.
- تنتهي الجلسة تلقائياً بعد مدة عدم النشاط المحددة في الإعدادات ← الجلسات.

### طباعة الباركود (الأصول الثابتة ← طباعة الباركود)
- نوع الرمز: **باركود خطي Code 128** أو **رمز QR** — يحتوي رقم الأصل.
- مقاسات جاهزة: ورق A4 (24 أو 21 أو 40 ملصقاً في الصفحة) أو طابعة ملصقات (رول) 50×25 و100×50 مم.
- محتوى الملصق: اسم المؤسسة، الشعار، اسم الأصل، الموقع/المبنى/الغرفة — مع عدد النسخ لكل أصل ومعاينة قبل الطباعة.
- الطباعة من: صفحة الباركود، أو زر "باركود المحدد" في قائمة الأصول، أو زر "طباعة الملصق" في صفحة الأصل.
- **قارئ الباركود:** امسح الملصق في خانة "قارئ الباركود" فيفتح الأصل مباشرة. (يمكن أيضاً المسح في خانة التصفية بأي قائمة.)
- **نصيحة للطباعة:** في نافذة الطباعة اختر الهوامش "بلا" (None) والمقياس 100%.

### نقل الأصول (الأصول الثابتة ← نقل الأصول) — شيت `AssetTransfers`
- **نقل جماعي:** حدد الأصول من القائمة ← "نقل المحدد"، أو من صفحة الأصل ← "نقل الأصل"، أو "نقل جديد" وامسح أرقام الأصول.
- **الوجهة:** اختر الغرفة (يُكتب المبنى والموقع) و/أو الوحدة الفرعية 2 (تُكتب الوحدات الأعلى) و/أو الإدارة والموظف المسؤول. الحقل الفارغ = بدون تغيير.
- **دورة العمل:** مسودة ← اعتماد ← **ترحيل** (عند الترحيل يتحدّث الأصل ودفاتره بالوجهة الجديدة).
- **محضر النقل:** طباعة مستند رسمي فيه "من/إلى" لكل أصل وخانات توقيع (المسلّم، المستلم، أمين العهدة، المعتمد).
- **سجل النقل:** من صفحة الأصل ← "سجل النقل" لرؤية كل حركات الأصل.
- **حماية:** لا يُسمح بنقلين مفتوحين لنفس الأصل، ولا يُرحَّل النقل إذا تغيّر وضع الأصل بعد إنشائه.
- صلاحية جديدة: **نقل الأصول** (دخول/إضافة/تعديل/حذف/اعتماد/ترحيل).

## الإصدار 5: القيود المحاسبية

> **للترقية:** انسخ `Code.gs` و`App` و`Styles`، شغّل `setup` مرة واحدة (يُنشئ شيتي `GLJournals` و`GLJournalLines`)، ثم انشر نسخة جديدة.

### القيود المحاسبية (المحاسبة ← القيود المحاسبية)
- **الرأس:** رقم القيد (تلقائي `JV-000001`)، نوع اليومية، البيان، التاريخ، المرجع.
- **التفاصيل:** سطر القيد، رقم الحساب (فرعي فقط)، الوحدة الفرعية 2 (تُكتب الوحدات الأعلى تلقائياً)، مدين، دائن، ملاحظة، مرجع.
- يظهر الفرق بين المدين والدائن مباشرة، ولا يُعتمد القيد إلا إذا كان **متوازناً**.
- دورة العمل: مسودة ← اعتماد ← ترحيل، مع طباعة القيد.

### القيود التلقائية
| العملية | القيد |
|---|---|
| ترحيل يومية الأصول | لكل سطر: حساب الأصل (من المجموعة) ↔ الحساب المقابل كطرف ثانٍ. مثال الإهلاك: من ح/ مصروف الإهلاك إلى ح/ مجمع الإهلاك |
| ترحيل نقل بين الوحدات | من ح/ الأصل (الوحدة الجديدة) إلى ح/ الأصل (الوحدة القديمة) بالتكلفة، ومن ح/ مجمع الإهلاك (القديمة) إلى ح/ مجمع الإهلاك (الجديدة) بالمجمع |

- القيود التلقائية تُرحَّل مباشرة، وتحمل المصدر ورقم المستند، ولا يمكن تعديلها.
- النقل الذي لا يغيّر الوحدات (موقع/غرفة/موظف فقط) لا ينشئ قيداً.
- **طباعة القيد** من صفحة يومية الأصول تعمل حتى قبل الترحيل (للمراجعة).

### حركات الأصول الثابتة (الأصول الثابتة ← حركات الأصول الثابتة)
كل حركات الأصل بأعمدة D365:
`JOURNALBATCHNUMBER, TRANSDATE, JOURNALNAME, TRANSACTIONTYPE, FIXEDASSETNUMBER, ASSETNAME, BOOKID, TEXT, DEBITAMOUNT, CREDITAMOUNT, OFFSETACCOUNTTYPE, OFFSETACCOUNT, OFFSET_OPERATINGUNIT, OFFSET_SUB1_OPERATINGUNIT, OFFSET_SUB2_OPERATINGUNIT, OFFSETACCOUNTDISPLAYVALUE`
مع تصفية بالأصل والنوع والحالة والتاريخ، والتصدير إلى Excel بنفس أسماء الأعمدة.

### منع تكرار الإهلاك
- لا يُقبل سطر إهلاك بتاريخ في شهر سبق إهلاكه (حتى "تاريخ آخر إهلاك").
- لا يُقبل سطر إهلاك ثانٍ غير مُرحّل لنفس الأصل والدفتر.
- يُعاد التحقق عند الترحيل، والمقترح التلقائي يستبعد الأصول التي لها إهلاك غير مُرحّل.

## الإصدار 6: التقارير المالية والقوائم المنسدلة القابلة للبحث

> **للترقية:** انسخ `Code.gs` و`App` و`Styles` و`Index`، شغّل `setup` مرة واحدة، ثم انشر نسخة جديدة.
> الترقية تغيّر اسم التطبيق تلقائياً إلى **"الإدارة المالية"** (إن كان الاسم القديم الافتراضي)، ويمكن تغييره من الإعدادات.

### التقارير المالية (المحاسبة ← التقارير المالية)
تعتمد على **القيود المحاسبية المُرحّلة فقط** (اليدوية والتلقائية)، مع تصفية بالفترة والوحدة (رئيسية/فرعية 1/فرعية 2)، وتصدير Excel وطباعة.

| التقرير | المحتوى |
|---|---|
| ميزان المراجعة | رصيد افتتاحي + حركة الفترة + رصيد ختامي (مدين/دائن) مجمّعة تحت الحسابات الرئيسية، مع فحص التوازن |
| دفتر الأستاذ | لحساب فرعي أو رئيسي (كل حساباته الفرعية) أو كل الحسابات: رصيد أول المدة، الحركات، الرصيد المتحرك. رقم القيد يفتح القيد |

- **نوع الحساب** يحدد مكانه: أصول/خصوم/حقوق ملكية في الميزانية، وإيرادات/مصروفات/أرباح وخسائر في قائمة الدخل.
- **تصنيف التدفق النقدي** (حقل جديد في الحساب): نقدية، تشغيلية، استثمارية، تمويلية. حدد "نقدية" لكل حسابات البنوك والصناديق.
  إن تُرك فارغاً: حسابات الأصول الثابتة = استثمارية، حقوق الملكية = تمويلية، الباقي = تشغيلية.
- الأرقام بين قوسين ( ) = سالبة أو دائنة.

### القوائم المنسدلة
- كل القوائم (الحسابات، الوحدات، الأصول، الموردين، أنواع المعاملات، الحالات…) أصبحت **قابلة للبحث** بالكود أو الاسم.
- البحث العربي يتجاهل الفروق بين (أ/إ/آ/ا) و(ة/ه) و(ى/ي) والتشكيل، ويُبرز الجزء المطابق.
- لوحة المفاتيح: ↓ ↑ للتنقل، Enter للاختيار، Esc للإغلاق.

## الإصدار 7: إقفال السنة المالية والعملات

> **للترقية:** انسخ `Code.gs` و`App` و`Styles`، شغّل `setup` مرة واحدة (يُنشئ `Currencies` و`ExchangeRates` و`FiscalYears`، ويضيف أسماء اليوميات `GJ` و`YE`، ويحوّل سطور القيود القديمة للعملة المحلية)، ثم انشر نسخة جديدة.

### إقفال السنة المالية (المحاسبة ← السنوات المالية والإقفال)
1. أنشئ السنة (اكتب `2026` فتُملأ الفترة 01-01 → 12-31 تلقائياً) وحدد **حساب الأرباح المحتجزة** (حقوق ملكية).
2. حدد السنة ← **إقفال السنة المحددة**: تظهر الإيرادات والمصروفات وصافي الربح قبل التأكيد.
3. الإقفال ينشئ **قيد إقفال** بتاريخ نهاية السنة يصفّر حسابات الإيرادات والمصروفات **لكل وحدة** ويرحّل الصافي إلى الأرباح المحتجزة.
4. بعد الإقفال يُمنع أي قيد أو سطر يومية أصول أو نقل بتاريخ داخل السنة.

- لا يمكن الإقفال مع وجود مستندات غير مُرحّلة في السنة، ولا قبل إقفال السنة السابقة.
- **إعادة الفتح** تحذف قيد الإقفال (ويجب فتح السنوات اللاحقة أولاً).
- قائمة الدخل تستبعد قيد الإقفال (تبقى تعرض ربح السنة)، وميزان المراجعة فيه خيار "قبل قيد الإقفال".
- صلاحية جديدة: **السنوات المالية والإقفال** (الإقفال وإعادة الفتح = صلاحية "ترحيل").

### العملات وأسعار الصرف (المحاسبة ← العملات وأسعار الصرف)
- **العملات**: الرمز (3 أحرف) والاسم. **أسعار الصرف**: العملة، ساري من تاريخ، السعر = وحدات محلية لكل وحدة أجنبية.
- في سطر القيد: **العملة وسعر الصرف** (يُملأ تلقائياً بآخر سعر ساري حتى تاريخ القيد ويمكن تعديله)، والمبالغ تُدخل بالعملة، ويُحسب **المبلغ المحلي** تلقائياً.
- التوازن والتقارير المالية بالعملة المحلية؛ دفتر الأستاذ يعرض مبلغ العملة الأجنبية بجانب البيان.

### تحسينات
- **صفحة دفتر الأصل** تعرض دفاتر الأصل المرتبط فقط؛ "دفاتر الأصول" من القائمة تعرض جدول كل الدفاتر.
- **سطور القيد** بشكل مدمج مثل D365: صفوف بارتفاع 28px، خلايا بدون حدود، أعمدة: الحساب، اسم الحساب، العملة، سعر الصرف، مدين، دائن، (المحلي)، الوحدة، ملاحظة، مرجع.
- **خيارات الطباعة** قبل كل طباعة: رأسي/أفقي، A4/A5/Letter، الهوامش — ويتذكر النظام اختيارك.
- القوائم المنسدلة لا تُفتح تلقائياً عند فتح النوافذ؛ تُفتح بالنقر أو الكتابة أو السهم ↓.

## الإصدار 8: العملاء والصناديق والبنوك والموازنة التقديرية

> بعد لصق الملفات الجديدة يكفي فتح التطبيق: تُنشأ الشيتات الجديدة تلقائياً (`Customers`، `BankAccounts`، `BankGroups`، `Budgets`)، وتُضاف أعمدة جديدة للموردين وسطور القيود.

### العملاء (العملاء ← العملاء) — شيت `Customers`
رقم العميل، اسم العميل، العنوان، الإيميل، رقم التليفون، العملة، حساب العميل في الدليل (افتراضياً `130100 ذمم العملاء`)، الرصيد الافتتاحي (مدين +).

### الصناديق والبنوك — شيت `BankAccounts`
رقم الصندوق/البنك، الاسم، العملة، الرصيد الافتتاحي (مدين +)، المجموعة (`CASH` الصناديق / `BANK` البنوك — تُدار من الإعدادات ← القوائم)، والحساب في الدليل. يُنشأ تلقائياً `BANK01` (110100) و`CASH01` (110200).

### الموردون
أُضيف لهم: العملة، الرصيد الافتتاحي (دائن +).

### الأرصدة الافتتاحية
من صفحة العملاء / الموردين / البنوك اضغط **ترحيل الأرصدة الافتتاحية** ← يُنشأ قيد مسودة بكل الأرصدة غير المُرحّلة مقابل حساب الأرصدة الافتتاحية (`310300`، قابل للتغيير من الإعدادات) ← اعتمد القيد ورحّله. بعد الترحيل لا يُعدَّل الرصيد في البطاقة (احذف القيد وهو مسودة أو اعمل قيد تسوية).

### القيد المحاسبي: نوع الحساب (مثل D365)
كل سطر قيد له **نوع الحساب**: حساب أستاذ / عميل / مورد / صندوق-بنك. عند اختيار عميل أو مورد أو بنك يُكتب حسابه في الدليل تلقائياً، وتُؤخذ عملته. في يومية الأصول، إذا كان الحساب المقابل هو حساب المورد يُسجَّل السطر باسم المورد فيظهر في كشف حسابه.

### التقارير (لكل نوع صفحة مستقلة: تقارير العملاء / تقارير الموردين / تقارير الصناديق والبنوك)
- **التقرير الإجمالي:** الرقم، الاسم، العملة، الرصيد الافتتاحي، حركة الفترة (مدين/دائن)، الرصيد الختامي، والختامي بالعملة المحلية. البنوك مجمّعة حسب المجموعة مع إجمالي لكل مجموعة.
- **كشف الحساب:** رصيد افتتاحي، كل حركة (التاريخ، رقم القيد كرابط، البيان، مدين، دائن، الرصيد التراكمي)، والرصيد الختامي.
- المبالغ بعملة الطرف. الرصيد الافتتاحي = ما قبل "من تاريخ" + قيد الأرصدة الافتتاحية. التقارير تعتمد على القيود المُرحّلة فقط.
- رصيد العميل والبنك = مدين − دائن، ورصيد المورد = دائن − مدين.
- طباعة (مع خيارات الاتجاه) وتصدير Excel.

### الموازنة التقديرية (المحاسبة ← إدخال الموازنة التقديرية) — شيت `Budgets`
السنة، رقم الحساب (اسم الحساب يُكتب تلقائياً)، الوحدة الفرعية 2 (الوحدة الرئيسية والفرعية 1 تُكتب تلقائياً، ويمكن تركها فارغة لموازنة على مستوى الشركة)، المبلغ التقديري، سنوي/شهري.
- **سنوي:** المبلغ للسنة كلها ويُوزّع بالتساوي على 12 شهراً.
- **شهري:** المبلغ لكل شهر.
- لا يُسمح بسطرين لنفس السنة والحساب والوحدة. يدعم الاستيراد والتصدير Excel.

### تقرير مراقبة الموازنة (المحاسبة ← مراقبة الموازنة)
رقم الحساب، اسم الحساب، الوحدة (حسب المستوى المختار: رئيسية / فرعية 1 / فرعية 2 / بدون)، التقديري، الفعلي، الفارق (الفعلي − التقديري)، نسبة الفارق.
- فلاتر: السنة، من شهر / إلى شهر، المستوى، الوحدة، "التجاوزات فقط".
- الأحمر = تجاوز: مصروف أعلى من التقديري، أو إيراد أقل منه.
- الفعلي من القيود المُرحّلة بدون قيد الإقفال.

### الصلاحيات الجديدة
`customers` (العملاء وتقاريرهم)، `banks` (الصناديق والبنوك وتقاريرها)، `budget` (الموازنة). المستخدمون الحاليون يأخذونها من قالب دورهم تلقائياً.

## الإصدار 9: سندات القبض والصرف، والموازنة بشكل رأس + تفاصيل

> تُنشأ تلقائياً الشيتات `CashVouchers` و`BudgetHeaders`، ويوميتان جديدتان `RV` (سندات القبض) و`PV` (سندات الصرف). سطور الموازنة القديمة من الإصدار 8 تُجمَّع تلقائياً في موازنات **معتمدة** (حسب السنة + سنوي/شهري + إيرادات/مصروفات) فلا يتغير تقرير المراقبة.

### سندات القبض والصرف (الصناديق والبنوك ← سندات القبض والصرف) — شيت `CashVouchers`
- زر **سند قبض جديد** أو **سند صرف جديد** ← اختر الطرف والصندوق/البنك والمبلغ ← **حفظ وترحيل**: يُنشأ القيد المُرحّل بضغطة واحدة.
  - **القبض:** من حـ/ الصندوق أو البنك ← إلى حـ/ العميل (أو المورد أو أي حساب).
  - **الصرف:** من حـ/ المورد (أو العميل أو حساب مصروف + وحدة) ← إلى حـ/ الصندوق أو البنك.
- الحقول: نوع السند، التاريخ، الصندوق/البنك (العملة وسعر الصرف يُملآن منه)، نوع الطرف (عميل/مورد/حساب أستاذ)، الطرف، الوحدة الفرعية 2 (للمصروفات)، المبلغ، طريقة الدفع (نقداً/شيك/تحويل)، رقم الشيك، البيان.
- الترقيم تلقائي: `RV-000001` للقبض و`PV-000001` للصرف (البادئة قابلة للتغيير من شيت Settings).
- المبلغ يُكتب **تفقيطاً** تحت النموذج وفي السند المطبوع ("فقط ... لا غير").
- **طباعة السند** بشكل سند قبض/صرف رسمي مع التوقيعات.
- يمكن الحفظ كمسودة ثم الترحيل لاحقاً. المسودة تُحذف، أما المُرحّل فيُ**لغى**: يُنشأ قيد عكسي مُرحّل بتاريخ الإلغاء، ويبقى السند بحالة "ملغى".
- الحركة تظهر فوراً في كشوف حساب العملاء والموردين والبنوك.
- صلاحية جديدة: `cashvouchers` (الترحيل والإلغاء = إجراء "ترحيل").

### الموازنة التقديرية مثل قيد اليومية (المحاسبة ← الموازنات التقديرية)
- **الرأس:** رقم الموازنة (`BG-000001` تلقائي)، سنة الموازنة، نوع الموازنة (إيرادات/مصروفات)، تاريخ الإدخال، سنوي/شهري، البيان، الحالة والاعتماد (اعتمد بواسطة وتاريخه)، الإجمالي.
- **التفاصيل:** رقم السطر، رقم الحساب، اسم الحساب، الوحدة الفرعية 2 (والفرعية 1 والرئيسية تظهر تلقائياً)، المبلغ التقديري، ملاحظات.
- قائمة الحسابات تعرض حسابات الإيرادات فقط في موازنة الإيرادات، وغير الإيرادات في موازنة المصروفات.
- لا يتكرر نفس الحساب والوحدة في نفس السنة، سواء داخل الموازنة نفسها أو مع موازنة أخرى.
- **استيراد سطور من Excel** بالأعمدة: `MAINACCOUNTID` (رقم الحساب)، `SUB2_OPERATINGUNIT` (الوحدة الفرعية 2)، `AMOUNT` (المبلغ التقديري)، `NOTE` (ملاحظات). تقبل العناوين بالعربي أيضاً. **تصدير السطور** يعطيك نفس الشكل كقالب.
- **اعتماد / إلغاء اعتماد**، والموازنة المعتمدة لا تُعدَّل. **تقرير مراقبة الموازنة يحسب الموازنات المعتمدة فقط.**
- طباعة الموازنة.

## الإصدار 10: فواتير المبيعات والمشتريات (دورة كاملة)

> تُنشأ تلقائياً الشيتات `Invoices` و`InvoiceLines`، ويوميتان `SI` (فواتير المبيعات) و`PI` (فواتير المشتريات). في الدليل الافتراضي تُضاف الحسابات: `410200` إيرادات المبيعات، `620100` مشتريات ومصروفات عامة، `220100` ضريبة القيمة المضافة - مخرجات، `140100` ضريبة القيمة المضافة - مدخلات.

### الدورة: فاتورة ← سند قبض/صرف ← كشف حساب
1. **الفاتورة:** العملاء ← فواتير المبيعات (أو الموردون ← فواتير المشتريات) ← فاتورة جديدة ← **حفظ وترحيل**.
   - **المبيعات:** من حـ/ العميل (الإجمالي) ← إلى حـ/ الإيرادات (لكل سطر بوحدته) + حـ/ ضريبة المخرجات.
   - **المشتريات:** من حـ/ المصروف (لكل سطر) + حـ/ ضريبة المدخلات ← إلى حـ/ المورد.
2. **التحصيل / السداد:** من الفاتورة المُرحّلة اضغط **تحصيل (سند قبض)** أو **سداد (سند صرف)**. يُفتح السند جاهزاً بالطرف والفاتورة والمبلغ المتبقي، فتعدّل المبلغ إن كان جزئياً ثم تضغط **حفظ وترحيل**.
   - يمكن أيضاً اختيار الفاتورة من حقل **سداد الفاتورة** داخل أي سند. القائمة تعرض فواتير الطرف غير المسددة ومتبقي كل واحدة.
3. **كشف الحساب:** الفاتورة والسندات تظهر فوراً في كشف حساب العميل أو المورد.

### الفاتورة
- **الرأس:** رقم الفاتورة (`SI-000001` / `PI-000001` تلقائي)، تاريخ الفاتورة، تاريخ الاستحقاق، العميل/المورد (العملة وسعر الصرف من بطاقته)، مرجع الطرف (رقم فاتورة المورد أو أمر الشراء)، البيان.
- **السطور:** البيان/الصنف، الحساب (افتراضي من الإعدادات)، الوحدة الفرعية 2، الكمية، سعر الوحدة، الإجمالي، نسبة الضريبة، الضريبة.
- **الأسفل:** الإجمالي قبل الضريبة، الضريبة، إجمالي الفاتورة مع التفقيط، ثم المسدد والمتبقي بعد الترحيل، وجدول بالتحصيلات أو المدفوعات المرتبطة.
- **حالة السداد:** غير مسددة / مسددة جزئياً / مسددة / **متأخرة** (تجاوزت تاريخ الاستحقاق). فلاتر القائمة: الكل، غير مسددة، متأخرة، مسددة، مسودات. وفيها عمود **المتبقي** مع الإجمالي.
- **طباعة الفاتورة** ببيانات العميل (العنوان والتليفون) والإجماليات والتفقيط والتوقيعات.
- **الحماية:**
  - لا يُقبل سند بمبلغ أكبر من المتبقي على الفاتورة.
  - سند القبض لفواتير المبيعات فقط، وسند الصرف لفواتير المشتريات فقط، ولنفس الطرف.
  - الفاتورة المسدد عليها شيء لا تُلغى قبل إلغاء سنداتها.
  - إلغاء سند مرتبط بفاتورة يعيد المبلغ إلى متبقي الفاتورة.
  - لا يُحذف عميل أو مورد له فواتير.
- **الإعدادات ← الفواتير والضريبة:** حساب المبيعات، حساب المشتريات، حسابا ضريبة المخرجات والمدخلات، ونسبة الضريبة الافتراضية.
- صلاحية جديدة: `invoices`.

## الإصدار 11: الأصناف، أعمار الديون، ترحيل الموازنة، ووحدة الفاتورة في الرأس

> تُنشأ تلقائياً الشيتات `ItemGroups` و`SalesItems` و`PurchaseItems` و`ItemUnits`. وحدات الأصناف الافتراضية: PCS قطعة، BOX علبة، KG، L، SRV خدمة، HR ساعة (تُعدَّل من الإعدادات ← القوائم). تُنشأ مجموعة `GEN` "أصناف عامة" مربوطة بحسابَي المبيعات والمشتريات الافتراضيين.

### الأصناف (القائمة ← الأصناف)
- **مجموعات الأصناف** (`ItemGroups`): رقم المجموعة، الاسم، **حساب المبيعات (الإيراد)**، **حساب المشتريات (المصروف)**. الربط المحاسبي يكون هنا.
- **أصناف البيع** (`SalesItems`): رقم الصنف، اسم الصنف، مجموعة الصنف، الوحدة، سعر البيع.
- **أصناف الشراء** (`PurchaseItems`): رقم الصنف، اسم الصنف، مجموعة الصنف، الوحدة، سعر الشراء.
- الصنف ← المجموعة ← الحساب. لا يُقبل صنف بيع في مجموعة بلا حساب مبيعات، ولا صنف شراء في مجموعة بلا حساب مشتريات.
- استيراد وتصدير Excel. لا تُحذف مجموعة لها أصناف، ولا صنف عليه فواتير.
- صلاحية جديدة: `items`.

### الفاتورة
- **الوحدة الفرعية 2 في رأس الفاتورة (إلزامية)**، والفرعية 1 والرئيسية تُكتبان تلقائياً. كل وحدة تبيع أو تشتري بفواتيرها، وكل سطور القيد (العميل/المورد، الإيراد/المصروف، الضريبة) تُسجَّل بوحدة الرأس.
- **السطر:** رقم الصنف ← يُكتب تلقائياً اسم الصنف والوحدة والسعر وحساب المجموعة، فتكتب الكمية فقط. يمكن أيضاً كتابة سطر بدون صنف (بيان + حساب).
- الفواتير القديمة: وحدة أول سطر تُنقل إلى الرأس تلقائياً.

### أعمار الديون (تقارير العملاء / تقارير الموردين ← تبويب أعمار الديون)
- الفواتير المُرحّلة غير المسددة **حتى تاريخ معيّن**: المسدد يُحسب من السندات المُرحّلة حتى ذلك التاريخ، فتقدر ترى الوضع في أي يوم سابق.
- الأعمدة: رقم العميل/المورد، الاسم، العملة، **لم يستحق، 0–30، 31–60، 61–90، أكثر من 90 يوماً**، الإجمالي. العمر = عدد الأيام من **تاريخ الاستحقاق** إلى تاريخ التقرير.
- ملخص أعلى التقرير: إجمالي المستحق، المتأخر ونسبته، وما تجاوز 90 يوماً.
- خيار **عرض الفواتير**: تحت كل طرف فواتيره، مع عدد أيام التأخير ورابط لكل فاتورة. وخيار **المتأخرون فقط**.
- الترتيب: الأكثر تأخراً أولاً. الألوان: برتقالي 61–90، وأحمر أكثر من 90.
- طباعة وExcel.
- ملاحظة: التقرير مبني على **الفواتير**؛ الأرصدة الافتتاحية والقيود اليدوية لا تدخله (تظهر في كشف الحساب).

### الموازنة: اعتماد ثم ترحيل مثل القيد
- **مسودة ← اعتماد ← ترحيل.** يمكن إلغاء الاعتماد قبل الترحيل، والموازنة المُرحّلة نهائية ولا تُعدَّل.
- **تقرير مراقبة الموازنة يحسب الموازنات المُرحّلة فقط.**
- الموازنات المعتمدة قبل هذا الإصدار تُرحَّل تلقائياً حتى لا يتغير التقرير.
- الترحيل يحتاج إجراء "ترحيل" في صلاحية `budget`، والمحاسب يملكه افتراضياً.

## الإصدار 12: الإشعارات الدائنة والمدينة، وصفحة "حسابي" لتغيير كلمة المرور

> تُضاف يوميتان `CN` (إشعارات دائنة) و`DN` (إشعارات مدينة)، وعمودان في شيت `Invoices`: `ORIGINVOICE` (الفاتورة الأصلية) و`CREDITAMOUNT` (المخصوم بإشعارات). الإشعارات تُحفظ في نفس شيت الفواتير بأنواع جديدة.

### أنواع الإشعارات
| النوع | الترقيم | أثره | القيد |
|---|---|---|---|
| **إشعار دائن للعميل** (مرتجع مبيعات / خصم) | `SCN-` | يخفض رصيد العميل ويُخصم من الفاتورة الأصلية | من حـ/ الإيراد + الضريبة ← إلى حـ/ العميل |
| **إشعار مدين للعميل** (فرق سعر، مصاريف) | `SDN-` | يزيد رصيد العميل ويُحصَّل مثل الفاتورة | من حـ/ العميل ← إلى حـ/ الإيراد + الضريبة |
| **إشعار مدين للمورد** (مرتجع مشتريات / خصم) | `PDN-` | يخفض رصيد المورد ويُخصم من فاتورته الأصلية | من حـ/ المورد ← إلى حـ/ المصروف + الضريبة |
| **إشعار دائن من المورد** (مبلغ إضافي له) | `PCN-` | يزيد رصيد المورد ويُسدَّد مثل الفاتورة | من حـ/ المصروف + الضريبة ← إلى حـ/ المورد |

### طريقة الاستخدام
- **الأسرع:** من فاتورة مُرحّلة اضغط **مرتجع / إشعار دائن** (أو **مرتجع / إشعار مدين** في المشتريات). يُفتح الإشعار جاهزاً بنفس العميل والوحدة والفاتورة الأصلية وسطور الفاتورة؛ عدّل الكميات المرتجعة ثم **حفظ وترحيل**. وزر **إشعار مدين** (أو **إشعار دائن** للمورد) لمبلغ إضافي.
- **أو من الصفحات الجديدة:** العملاء ← إشعارات العملاء (دائن / مدين)، والموردون ← إشعارات الموردين (مدين / دائن).
- **الفاتورة** تعرض: المسدد، **المخصوم بإشعارات**، والمتبقي، مع جدول الإشعارات المرتبطة بها.
- **قواعد الإشعار الدائن (المرتجع):**
  - الفاتورة الأصلية إلزامية، ونفس العميل/المورد، ومُرحّلة.
  - لا يتجاوز الإشعار ما لم يُخصم بعد من قيمة الفاتورة.
  - إذا كانت الفاتورة مسددة وتجاوز المرتجع المتبقي، يصبح الفرق **رصيداً دائناً للعميل** يظهر في كشف حسابه، ويُرد له بسند صرف (نوع الطرف: عميل).
- لا تُلغى فاتورة عليها إشعارات دائنة قبل إلغاء الإشعارات. وإلغاء الإشعار يعيد المبلغ إلى متبقي الفاتورة.
- تظهر الإشعارات في كشف الحساب، والإشعارات المدينة تدخل **أعمار الديون**، والدائنة تخفض الفاتورة الأصلية فيه حتى تاريخ التقرير.
- المرتجع يُقيَّد على نفس حسابات الأصناف (الإيراد أو المصروف). إن أردت حساب "مرتجعات المبيعات" مستقلاً، اكتب الحساب يدوياً في سطر الإشعار.

### حسابي وكلمة المرور (الإدارة ← حسابي وكلمة المرور)
- صفحة متاحة **لكل مستخدم** بدون صلاحية خاصة، وأيضاً من قائمة المستخدم أعلى الشاشة ← حسابي.
- تعرض بيانات المستخدم وتسمح بتغيير كلمة المرور: الحالية، ثم الجديدة، ثم التأكيد.
- الشروط تظهر أثناء الكتابة: 8 أحرف على الأقل، وحروف وأرقام، وتطابق التأكيد. وفيها خيار "إظهار كلمات المرور".
- نسيان كلمة المرور: المدير يعيد تعيينها من صفحة المستخدمين، ويُطلب من المستخدم تغييرها عند الدخول.

## الإصدار 13: حسابات مستقلة لمردودات المبيعات والمشتريات

> في الدليل الافتراضي يُضاف حسابان: `410900` مردودات ومسموحات المبيعات (تحت الإيرادات)، و`620900` مردودات ومسموحات المشتريات (تحت المصروفات التشغيلية). يُربطان تلقائياً بالإعدادات وبمجموعة `GEN`.

### أين تُحدَّد الحسابات
- **مجموعات الأصناف:** حقلان جديدان: **حساب مردودات المبيعات** و**حساب مردودات المشتريات**. كل مجموعة يمكن أن يكون لها حساب مردودات خاص.
- **الإعدادات ← الفواتير والضريبة:** حساب مردودات المبيعات الافتراضي، وحساب مردودات المشتريات الافتراضي.

### كيف يُختار حساب سطر المرتجع (إشعار دائن للعميل / إشعار مدين للمورد)
1. حساب المردودات من **مجموعة الصنف**.
2. إن لم يوجد: حساب المردودات **الافتراضي من الإعدادات**.
3. إن لم يوجد: حساب المبيعات/المشتريات العادي (كما في الإصدار 12).

- ينطبق ذلك عند إنشاء المرتجع من الفاتورة، وعند اختيار صنف في سطر الإشعار، وعلى سطر بدون صنف (مثل خصم تعجيل دفع).
- يمكن دائماً تغيير الحساب يدوياً في السطر قبل الترحيل.
- الإشعارات المدينة للعميل والدائنة من المورد (مبالغ إضافية) تبقى على حسابات المبيعات/المشتريات العادية.

### الأثر في التقارير
- **قائمة الدخل:** المردودات تظهر بين قوسين تحت الإيرادات والمصروفات، فيظهر **صافي المبيعات** و**صافي المشتريات** مباشرة.
- ميزان المراجعة ودفتر الأستاذ يعرضان حسابات المردودات منفصلة.
- الإشعارات المُرحّلة قبل هذا الإصدار تبقى على حساباتها كما هي، فلا تُعدَّل القيود القديمة.

## الإصدار 14: الأرصدة الافتتاحية للأصول في القوائم المالية، ولوحة المبيعات والمشتريات

### لماذا لم تظهر الأصول في القوائم المالية؟
- **سجل الأصول وتقارير الأصول** تقرأ من **دفاتر الأصول** (سعر الاقتناء ومجمع الإهلاك).
- **القوائم المالية** (ميزان المراجعة، الميزانية، قائمة الدخل) تقرأ من **القيود المُرحّلة فقط**.
- الأصول المستوردة من D365 (أو المُدخلة مباشرة في الدفتر) لها قيم في الدفتر بدون قيد، فتظهر في السجل ولا تظهر في القوائم.

### الحل: قيد الأرصدة الافتتاحية للأصول
1. **دفاتر الأصول ← قيد الأرصدة الافتتاحية للأصول.** تظهر نافذة بعدد الأصول والتكلفة ومجمع الإهلاك وصافي القيمة، وقائمة الأصول.
2. اختر **التاريخ**: يُفضّل آخر يوم قبل بداية السنة المالية (مثل 31-12-2025) ليظهر كرصيد افتتاحي في ميزان المراجعة.
3. اختر **حساب الأرصدة الافتتاحية**. إن كان دليلك مخصصاً، أنشئ حساباً في حقوق الملكية (مثل "أرصدة افتتاحية") واختره.
4. **إنشاء القيد** (مسودة) ← اعتماد ← ترحيل.

**شكل القيد:**
- مدين: حساب الأصل من مجموعة الأصل.
- دائن: حساب مجمع الإهلاك من مجموعة الأصل.
- دائن: حساب الأرصدة الافتتاحية بصافي القيمة.

السطور مجمّعة حسب الحساب والوحدة التشغيلية، فتظهر الأصول في القوائم حسب كل وحدة.

### قواعد الحساب
- يُحسب **الدفتر الأساسي** فقط (General). دفاتر الضريبة الإضافية لا تُكرَّر.
- يدخل فقط **الجزء غير المُرحّل** عبر يومية الأصول. الأصل الذي اقتُني عبر اليومية لا يُكرَّر.
- يدخل فقط الدفتر بحالة مفتوح أو موقوف.
- كل دفتر يُسجَّل عليه رقم القيد (`OPENINGVOUCHER`) والمبالغ المُقيّدة، فلا يدخل قيداً افتتاحياً مرتين. الأصول التي تُستورد لاحقاً تدخل قيداً جديداً عند تشغيل الزر مرة أخرى.
- بعد ترحيل القيد لا يُعدَّل سعر الاقتناء أو مجمع الإهلاك يدوياً في الدفتر. التعديل يكون عبر يومية الأصول (تسوية اقتناء / تسوية إهلاك)، حتى يبقى الدفتر والقيود متطابقين.
- إذا كانت مجموعة أصل بدون حساب أصل أو حساب مجمع إهلاك، تعرض النافذة القائمة ولا تنشئ القيد حتى تكتمل الحسابات.
- **تنبيه في التقارير المالية:** يظهر شريط أصفر إذا وُجدت أصول قيمها غير مُقيّدة، مع رابط مباشر لإنشاء القيد.

### لوحة المبيعات والمشتريات (لوحة المعلومات ← تبويب «المبيعات والمشتريات»)
- تبويب داخل لوحة المعلومات بجوار «نظرة عامة»، ويظهر لمن له صلاحية `invoices`.
- **المبالغ:** بالعملة المحلية **قبل الضريبة**، للسنة المختارة.
- **البطاقات:**
  - صافي المبيعات وصافي المشتريات (بعد المرتجعات)، والفرق بينهما (مؤشر تقريبي وليس صافي الربح).
  - نسبة مرتجعات المبيعات.
  - المستحق من العملاء وللموردين مع المتأخر منه.
- **رسم شهري:** أعمدة صافي المبيعات (أزرق) والمشتريات (برتقالي). مرّر المؤشر على أي شهر لترى التفاصيل والمرتجعات. وخيار **عرض كجدول**.
- **أكبر العملاء وأكبر الموردين:** أكبر 8 لكل منهما.
- **أكثر الفواتير تأخراً:** مع عدد أيام التأخير ورابط لكل فاتورة.
- تصدير Excel.

## اقتراحات للمرحلة القادمة

- طباعة ملصقات باركود/QR للأصول.
- نقل الأصول بين المواقع مع سجل تاريخي.
- سجل تدقيق (Audit log) لكل التعديلات.
- استبعاد الأصول (بيع/تخريد) مع حساب الربح والخسارة.
